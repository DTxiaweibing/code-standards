# 测试细则（R13）

测试不是"有空再补"，是**改逻辑的交付条件**。没有测试的改动不算完成。

## 什么时候必须有测试

| 改动 | 要求 |
|---|---|
| 新增/修改业务逻辑、算法、状态机 | 必须有单元测试 |
| 修 bug | 必须先有能复现的失败用例，再修 |
| 改公共接口、数据结构、DB schema | 必须有契约/集成测试 |
| 改权限、金额、并发、迁移 | 必须有边界与错误路径用例 |
| 纯文案、注释、格式、依赖升级（无行为变化） | 可免 |

## 分层

| 层 | 范围 | 速度 | 占比建议 |
|---|---|---|---|
| 单元 | 纯函数、领域模型、校验器 | 毫秒 | ~70% |
| 集成 | 真实 DB / HTTP / 文件系统边界 | 秒 | ~20% |
| 端到端 | 关键用户路径（登录、下单、支付） | 十秒级 | ~10% |

不要用 E2E 覆盖本可以单元测的分支——慢且脆。

## 写法要求

- 命名表达意图：`shouldRejectExpiredToken` / `test_parse_returns_empty_for_blank`
- **一个用例一个行为**；断言失败信息要能直接定位
- 必测四类：正常路径、边界值、错误路径、权限/异常状态
- 测试与源码同目录（`*.test.ts` / `test_*.py` / `*Test.java`），便于一起移动
- 测试文件不受 R2 函数长度限制（E3 豁免），但仍建议一个用例不超过一屏

## 禁止

- `sleep(2)` 等固定等待——用轮询/事件/注入时钟
- 依赖真实网络、真实时间、未固定随机数
- 用例之间共享可变状态、依赖执行顺序
- 无理由 `skip` / `only` / 注释掉失败用例
- 只断言"不抛异常"而没有实质断言

## 覆盖率

- **新增/修改的代码**：行覆盖 ≥ 70%，核心领域（钱、权限、状态机）≥ 85%
- 不追求全仓数字；覆盖率是下限，不是目标
- 覆盖率下降时必须在 PR 里解释

## 命令

| 语言 | 测试 | 覆盖率 |
|---|---|---|
| TS/JS | `vitest run` / `jest --ci` | `--coverage` |
| Python | `pytest -q` | `pytest --cov` |
| Java | `mvn test` / `gradle test` | JaCoCo |
| Go | `go test ./...` | `go test -cover ./...` |
| Rust | `cargo test` | `cargo tarpaulin` |
| C/C++ | `ctest` | gcov/lcov |

## 判定

- 测试失败 = 任务未完成，禁止"先合并，稍后修"
- flaky 用例视为 bug：要么修到稳定，要么删除并说明
- 无人维护的测试（永远通过、从不失败）应删除，不要留假安全感
