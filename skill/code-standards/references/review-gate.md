# 审查门禁与问题台账

配 R11。核心原则：**证据先于声明**——没跑验证、没更新台账，就不算完成。

## L1 自查清单（每完成一个可评审单元）

- [ ] `review-check.ps1` 无新增 P0/P1
- [ ] 本次 diff ≤ 400 行（超了说明任务没拆够，先拆）
- [ ] 每个改动都有验证：测试 / 手动步骤 / 截图，至少一种
- [ ] 没有空 `catch`、没有吞异常、没有注释掉的旧代码
- [ ] 公共 API 有注释；新增 `TODO` 已进台账
- [ ] 没有跨模块深层 import；新模块有单一入口
- [ ] 接口/数据结构变更已同步调用方与文档
- [ ] 台账已更新（新增或关闭）

## 什么时候升级到 L2（独立评审）

- 改动跨 ≥3 个文件或 ≥2 个模块
- 改了公共接口、数据结构、数据库 schema
- 涉及权限、加密、支付、并发、迁移
- 连续两次 L1 出现同类问题（说明自查视角有盲区）

## L2 怎么做才有效

- **另起 subagent**，只给：验收标准 + `git diff` + 相关文件清单
- **不给**：本次会话历史、你的结论、你的自我评价
- 要求输出：按 P0–P3 分级 + 明确「放行 / 不放行」
- reviewer 说“没问题”也要看证据：它跑了什么、读了哪些文件

## 台账

位置：项目根 `.review/ledger.md`，进 git。
生成：`review-check.ps1 -Path . -Ledger .review/ledger.md -Append`

| 字段 | 说明 |
|---|---|
| ID | `R-001` 递增，永不复用 |
| 级别 | P0 / P1 / P2 / P3 |
| 类别 | file-size / func-size / lint / test / security / perf / design |
| 位置 | `file:line`（相对项目根） |
| 问题 | 一句话，可验证 |
| 状态 | open / fixed / deferred / waived |
| 决定 | 谁定的、为什么 |
| 触发条件 | `deferred` 必填，否则不许延期 |

## 铁律

1. **只增不删**，修完标 `fixed` 并附提交号
2. `deferred` 必须写触发条件，没有触发条件就现在修或降级 P3
3. **P0 禁止延期**；P1 延期必须人工确认并写触发条件，否则 open 状态阻断合并
4. 每次 L1/L2 结束必须更新台账，否则视为审查未完成
5. `waived` 必须引用 E1–E7 中的具体豁免类别，且只能由人确认
6. 不许把台账当垃圾桶：连续两个版本没动过的 `deferred` 要么修要么标 `wontfix`

## 严重级别

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 数据丢失、安全漏洞、必现崩溃 | 立即停手修 |
| P1 | 功能错误、契约破坏、**本次改动新增**的规范硬规则违规（由 pre-commit 直接拦截） | 本任务内修 |
| P2 | 存量超限（file-size / func-size）、重复代码、缺测试；≥1000 行的存量文件升为 P1 | 排期修，记台账 |
| P3 | 风格、提示、可选优化 | 可延期，写触发条件 |

```markdown
| R-001 | P2 | file-size | app/src/main/java/.../MixCalcActivity.java:1 | 文件 1751 有效行 > 500 | open | | 拆分该 Activity 时 |
| R-002 | P1 | func-size | .../MixCalcTableView.java:414 | onTouchEvent 71 行 > 50 | open | | |
| R-003 | P3 | lint | .../utils.ts:88 | TODO 无负责人 | fixed (a1b2c3d) | | |
```
